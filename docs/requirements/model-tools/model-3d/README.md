# 模型小工具 / 3D 模型构建 LEGO：功能需求草案

> 状态：规划中；页面、菜单项、接口与求解器均未按本草案实现。
>
> 所属菜单组：[模型小工具](../README.md)；对应[菜单级设计草案](../../../design/model-tools/model-3d/README.md)。

## 用户目标与预期流程

用户提供连续 3D 模型与目标物理尺寸，希望获得在该尺寸下可拼搭、尽量接近原形的 LEGO 模型，并最终导出单个 LDraw 文件。形状不得通过非等比缩放变形。

计划将其作为“模型小工具”下独立的 3D 功能入口，与当前 2D 模型工具并列。具体菜单文案、路由、源模型格式、尺寸输入方式、结果预览与下载交互，尚待产品和验证结果确定。

## 功能边界

- 可拼搭性是硬约束，形状相似性是优化目标。颜色、成本、零件库存、结构强度与装配步骤的优先级尚未确定。
- 连续几何分析用于判断 Shape 是否值得继续分块；局部 LEGO 求解负责零件组合。不得把“几何规律简单”直接视为“实际容易拼搭”。
- 分块判断应基于目标 LEGO 尺度，不让低于可表达分辨率的网格细节驱动分块。
- 最终可输出 LDraw 是整体目标，当前研究阶段只验证 Split / Build 决策，不承诺可用的端到端生成能力。

## 阶段性验收问题

1. 建立典型局部 Shape 集合，并标记哪些值得继续分块。
2. 验证 Constant、Taper、Bend、Bulge 能否覆盖多数“不值得继续分”的局部 Shape；覆盖率不足时先修正几何语言。
3. 验证合理的候选切分是否降低子 Shape 的描述难度，避免分块只增加边界成本。
4. 局部 LEGO 求解器可用后，再检验几何指标与形状误差、零件数、搜索成本及成功率之间的关系。

验收数据集、指标阈值和产品可接受质量仍需实验确定；当前不得据此宣称功能可用。

## i18n 与内容分类

未来菜单、输入提示、任务进度、失败状态和导出中的人类可读元数据使用现有语义 key 与资源治理；模型名称和上传文件名按用户原文保存，必要时记录 `contentLocale`。尺寸、算法标识、状态、LDraw 零件编号及 JSON 字段是机器数据，不翻译。若采用异步任务，创建时冻结 locale/timezone；若生成导出，使用版本化服务端资源和冻结的 `ExportContext`。
