## 1. 功能目标

模型广场为已登录用户提供公开 Component 发布动态流，并提供只看当前用户订阅对象发布动态的个人视图。用户可以
搜索公共动态、查看发布内容与派生图片、收藏他人的 Component、进入 Component 详情，以及管理自己的订阅关系。

广场以“版本发布事件”为内容单位，而不是以 Component 去重。同一 Component 多次发布时，每次发布都可以形成一张
独立卡片，用户能够理解版本、修订号、发布说明和发布时间的变化。

## 2. 用户与内容准入

- 使用者必须已经登录；actor 身份只能来自当前认证会话，不能由请求指定。
- 公共页签面向所有当前公开可见的用户 Component 发布事件，不以当前用户是否订阅为成员资格条件。
- 个人订阅页签只读取当前用户仍处于 active 状态的 Watch 所对应的发布事件。
- 广场只展示未删除、仍为 active 且具有可见发布版本的 Component；草稿、已删除内容及官方 Component 不进入公共
  发布动态。
- 发布事件必须已经达到图片处理终态才进入广场。图片成功时展示派生图片；图片处理最终失败时仍保留发布事件并以
  占位图展示；处理中事件暂不出现。
- Watch 和 Star 是互相独立的关系：收藏不会自动订阅，订阅也不会自动收藏或扩大内容访问权限。

## 3. 页面与页签导航

页面提供两个页签：

| 页签 | URL | 内容范围 |
|---|---|---|
| 公共 | `/model-plaza` | 全部符合准入条件的用户 Component 发布事件 |
| 个人订阅 | `/model-plaza?tab=subscriptions` | 当前用户 active Watch 对应、位于所选时间窗口内的发布事件 |

- 缺失或未知 `tab` 参数时进入公共页签。
- 当前页签写入 URL，刷新、浏览器前进后退和复制链接后必须恢复相同页签。
- 切换页签时不得混用两类 Feed 的结果、游标、搜索条件或加载状态。
- 模型广场不初始化个人仓库的目录、上传、候选确认或版本编辑状态。

## 4. 公共动态

### 4.1 首屏、搜索与刷新

1. 进入公共页签后自动读取首屏，每批最多展示 20 条事件。
2. 未填写搜索条件时按动态顺序浏览全部符合准入条件的发布事件。
3. 搜索框支持 Component 用户原始名称或完整 Component ID，输入最长 200 个字符；提交时去除首尾空白。
4. 搜索只在用户提交后生效。生效条件以标签形式显示，并可单独清除；清除后重新读取无筛选首屏。
5. 搜索条件必须绑定后续页游标；不得拿旧条件的游标继续另一项搜索。
6. 点击刷新时丢弃现有结果和游标，并用当前已提交的搜索条件重新读取首屏。

### 4.2 排序与连续加载

- 公共动态按事件达到可展示终态的时间倒序排列，并以事件 ID 作为稳定的唯一决胜条件。
- 卡片显示的发布时间仍是不可变发布事件的发生时间，不把图片完成时间冒充发布时间。
- 页面不计算或展示精确总数，使用不透明 keyset cursor 连续加载。
- 页面接近底部时自动加载下一批，同时保留“加载更多”按钮作为无自动观察能力环境和重试入口。
- 续页请求必须单飞；搜索、刷新或切换页签后返回的旧响应不能污染当前列表。
- 追加结果按事件 ID 去重，不按 Component ID 合并。同一 Component 的不同发布事件必须保留。

## 5. 个人订阅动态

### 5.1 时间窗口

- 默认展示最近 30 天，可切换最近 7 天、30 天或 90 天。
- 切换时间窗口时丢弃已有结果和游标，以当前时间重新计算首屏窗口起点。
- 后续页必须沿用首屏游标中冻结的窗口，不随翻页时钟继续移动。
- 当前 Watch 是 read-time 成员资格：取消订阅后下一次读取立即不再出现；重新订阅后按新的 active Watch 关系参与
  读取。
- 当前既有语义允许“早于本次 Watch、但仍位于所选时间窗口内”的发布事件出现，页面不能暗示只展示订阅之后的
  新事件。

### 5.2 加载与管理入口

- 每批最多展示 20 条事件，不计算精确总数，按事件时间和事件 ID 稳定 keyset 续页。
- 页面接近底部时自动续页，并保留“加载更多”按钮；追加结果按事件 ID 去重且不得在前端重新排序。
- 切换界面语言、时间窗口或手动刷新时重读首屏，并废弃先前尚未返回的请求。
- “管理订阅”进入 `/component-repo/watches`。该页面负责搜索、浏览和取消订阅关系，不在 Feed 页签内复制一份可编辑
  的订阅列表。
- 订阅管理发生变化后，以重新进入或刷新订阅 Feed 的服务端结果为准，不在两个路由之间维护临时共享列表。

## 6. 发布事件卡片

公共和个人订阅页签使用相同的事件卡片。每张卡片应展示：

- 发布人：当前只显示匿名头像和缩短后的稳定用户 ID，不推断邮箱或昵称。
- 事件发生时间：按当前界面 locale 格式化。
- Component 展示名称和详情链接。
- 事件发生时的版本号与修订号；不能用当前版本替代历史事件版本。
- Component 分类；分类为空时显示“未分类”。
- 1200 × 800、3:2 的派生图片；图片不可用时显示统一占位图。
- Component 描述；描述为空时显示本地化缺省提示。
- 本次发布说明；只有存在非空发布说明时才展示，并保留作者内容语言。
- 当前 Star 数量、当前用户的 Star 状态以及进入 Component 详情的操作。

卡片中的 Component 名称、描述和关系状态是当前可见投影；事件 ID、事件版本、修订号、发布人、发布时间与发布说明
属于不可变发布事实，两类数据不得相互替代。

## 7. Star 与详情交互

- 当前用户不是 Component owner 时，卡片显示可操作的收藏/取消收藏按钮及数量。
- 当前用户是 owner 时不显示收藏按钮，只展示收藏数量，避免收藏自己的 Component。
- 同一页面可能包含同一 Component 的多个发布事件。任一卡片 Star 状态变化后，该 Component 的全部可见卡片必须
  同步更新状态和数量。
- Star 操作采用即时反馈并在请求期间禁止重复提交；失败时重新读取权威首屏，避免长期保留错误的乐观状态。
- 成功后显示本地化结果提示。Star 不改变公共 Feed 成员资格，也不创建 Watch。
- 卡片标题和“详情”均进入 `/component-repo/components/:componentId`；详情读取仍执行自己的可见性与权限校验。

## 8. 加载、空状态与异常

| 场景 | 用户可观察行为 |
|---|---|
| 公共首屏加载 | 清空旧页并显示加载状态 |
| 公共 Feed 为空 | 提示暂时没有公开发布动态 |
| 公共搜索无结果 | 明确提示没有匹配组件，并建议调整搜索词 |
| 个人订阅首屏加载 | 显示订阅动态加载状态 |
| 订阅窗口无结果 | 提示所选时间范围内没有发布更新 |
| 续页加载 | 保留已加载卡片，加载按钮进入处理中状态 |
| Feed 请求失败 | 保留可用内容时展示结构化错误，并允许刷新或再次加载 |
| 派生图片不可用 | 只将对应卡片降级为占位图，不让整页失败，也不撤销已发布事件 |
| Star 请求失败 | 展示错误并重读权威状态，不让同一 Component 的多张卡片状态分裂 |

API 错误必须使用稳定 `code + params` 由前端本地化，不得暴露 SQL、对象存储 key、渲染器路径、进程错误或堆栈。

## 9. 多语言、内容与可访问性要求

- 页签、搜索、刷新、加载、空状态、Star、详情和管理入口使用 typed semantic keys，不得在组件内硬编码中英文。
- `tab=subscriptions`、Component/Event/Version ID、cursor、状态和版本号属于机器值，不翻译。
- 用户 Component 的名称、描述和发布说明按作者原文及 `contentLocale` 展示，不在线机器翻译。
- 官方内容若在相关投影中出现，只能选择 reviewed translation；draft/rejected 不可泄露。
- 日期与 Star 数量按当前 locale 格式化；切换 locale 后两个 Feed 都应重新读取首屏数据。
- 页签通过链接和 `aria-current` 表达选中状态；Feed 使用可识别的 feed 语义。
- 图像替代文本包含 Component 展示名称；装饰图标不参与读屏。
- Star、刷新、加载更多和清除搜索条件均使用原生按钮语义，支持键盘操作并提供状态对应的可访问名称。

## 10. 不在当前范围内

- 不在广场中创建、上传、编辑、发布或删除 Component；这些操作属于“我的模型”。
- 不提供公共用户资料页、头像上传、昵称或按发布人筛选。
- 不提供公共 Feed 的 Watch 过滤、分类筛选、精确总数或页码跳转。
- 个人订阅页签当前不提供名称搜索或分类筛选；这些能力只存在于独立订阅管理页。
- 不在浏览器下载 GLB 即时生成 Feed 图片，也不允许 Feed 请求同步触发渲染。
- 不把图片生成成功作为 Component 发布成功的前置条件。
- 不推断缺少发布领域事件的历史版本，也不把多次发布合并为一张“最新 Component”卡片。

## 11. 验收条件

1. 未带或带未知 `tab` 参数进入 `/model-plaza` 时显示公共页签；`tab=subscriptions` 显示个人订阅页签。
2. 刷新、前进后退和复制链接后仍恢复同一页签，两个页签的结果和 cursor 不串用。
3. 公共页签展示所有符合准入条件的用户发布事件，Watch 状态不会增减公共候选集合。
4. 同一 Component 连续发布两个版本时出现两张有独立 event ID、版本、修订号和发布时间的卡片。
5. 公共搜索能够按用户原始名称或完整 ID 查找，清除条件后恢复无筛选首屏，条件变化后旧 cursor 被拒绝或废弃。
6. ready 事件显示 1200 × 800 图片；fallback 事件显示占位图；pending 事件不出现在 Feed。
7. 公共和个人订阅页签使用相同卡片结构，并都能进入对应 Component 详情。
8. 个人订阅默认 30 天，可切换 7/30/90 天；续页沿用冻结窗口并保持稳定顺序。
9. 当前用户取消 Watch 后，下一次读取不再返回该 Component 事件；公共页签不受影响。
10. 非 owner 可以 Star/Unstar，owner 只看到数量；同一 Component 的多张卡片同步关系状态。
11. 自动续页与“加载更多”按钮均可工作，重复页按 event ID 去重，不计算或伪造精确总数。
12. 中文和英文界面、键盘操作、焦点、加载、空结果、错误、无图和响应式卡片布局通过浏览器验收。

## 12. 上线状态与已知限制

- 仓库已实现独立广场壳层、公共/个人订阅页签、共享事件卡片、keyset 续页、Star、终态派生图片和订阅管理入口，
  并有前端、Go、PostgreSQL 与规模计划验证证据。
- 真实 Supabase schema 已升级到 Goose v24；这不等同于当前 Go API、前端和 Feed Render Worker 已发布。
- Blender Cycles renderer v4、Component Preview v6、真实派生图片、双页签响应式布局和完整浏览器流程仍需在目标服务器
  联合验收。
- 发布人公开资料尚未建模，因此只能显示缩短用户 ID。
- v23 将已有发布事件回填为 fallback；v16 以前没有领域事件的历史发布版本不会被推断进 Feed。
- 公共 Feed 已以 100,000 事件验证查询形状，个人 Feed 按每 actor 最多约 1,000 active Watch 的当前容量规划；本地
  测试时间只证明查询形状，不是生产 SLO。

清理项、部署证据和客观关闭条件由[组件广场详细设计](../../../design/model-plaza/model-plaza/README.md#7-清理项)、
[公共 Feed](../../../component_repo/public_feed.md)与[Watch](../../../design/my-models/component-repo/watch.md)维护；本需求文档不把
仓库实现、数据库迁移和生产发布混为同一状态。
