# 脉络五：验证顺序与证据

> 状态：实验计划，尚无 benchmark 或求解器对照结果。返回[Shape 分块总览](../../../lego_shape_decomposition_design.md)。

## 核心假设

首先验证“Constant / Taper / Bend / Bulge 是否能覆盖多数已经不值得继续分的局部 Shape”，然后验证“几何上更易描述是否对应实际 LEGO 求解更好”。若第一项不成立，应修改 Pattern 语言；若第二项相关性弱，应重新定义 Split 决策，而不是继续调手工权重。

## 逐级实验

| 阶段 | 数据与操作 | 需要观察的结果 |
|---|---|---|
| A. 局部 Shape 集合 | 收集约 20～50 个头部、躯干、肢体、尾巴、翼、车身、轮拱、屋顶、斜面、连接区等例子；人工标记是否值得继续分 | 标注一致性、尺度分布、难例与失败类型 |
| B. Pattern 覆盖率 | 对“不值得继续分”的例子，选择最佳轴并拟合四种 Pattern | 覆盖率、各类残差、强迫归类的反例；原稿中的 80～90% 与 40～50% 仅是讨论性参照，不是验收阈值 |
| C. Split 解释力 | 对“值得继续分”的例子生成候选，分别拟合父块与子块 | 人工认可的切法是否降低误差；切割成本是否抵消收益 |
| D. LEGO Solver 对照 | 在局部求解器可用后，记录形状误差、零件数、搜索成本和成功率 | PatternError / Split 指标与实际可拼搭结果的相关性及反例 |

## 实现先后

1. 定义 Shape 分析结果，包含目标尺度、候选轴、截面、轴可信度和 Pattern 拟合记录。
2. 先做 PCA/OBB、截面采样与 Constant 基线，再逐个加入 Taper、Bend、Bulge。
3. 用局部 Shape 集合审查 Pattern 语言，覆盖不足先改语言。
4. 再做候选 Split 生成与多维前后对照；根据证据决定正式 SplitGain。
5. 最后与真实局部 LEGO Solver 对照；在此之前不宣称几何评分可以预测 LEGO 构建成功。

## 当前阶段不展开

真实零件召回、Beam Search、局部解集合、块间接口、Merge 重求解、装配路径、结构强度与 LDraw placement 属于 Build / Merge 阶段。这里仅把它们作为分块成本和最终验证的依赖，不提前设计完整实现。
