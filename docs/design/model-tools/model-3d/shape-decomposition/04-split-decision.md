# 脉络四：Split / Build 决策

> 状态：决策结构已明确，收益公式与阈值待实验。返回[Shape 分块总览](../../../lego_shape_decomposition_design.md)。

## 要回答的问题

何时停止几何分解并进入局部 LEGO Build？不使用“没有细腰”“足够凸”“Box 填充率达到某值”或固定递归深度作为硬规则。对当前 Shape 实际尝试一次候选分块，判断分后是否得到明显更易描述且值得后续拼搭的子问题。

上游的[几何语言拟合](./02-pattern-language.md)给出“不切时”的描述，[候选分块](./03-split-candidates.md)给出“可以怎么切”。本环节比较的是**同一个问题的两种处理方式**，所以子块必须各自重新选轴并拟合；沿用父轴会把父块不适用的表示强加给子块。这里得出的只是几何代理决策，是否对应真实 LEGO 构建收益仍需[实验验证](./05-validation.md)。

## 递归决策

```text
分析 S 的最佳轴与 Pattern
  → 生成有目标尺度意义的二分候选
  → 为每个候选的 S1、S2 重新选轴并拟合
  → 比较分前/分后的收益和切割代价
  → 有显著净收益：递归 Split；否则：Build(S)
```

`Gain = C(S) - [(V1/V)C(S1) + (V2/V)C(S2)] - λ·CutCost` 只是说明比较关系的**概念式**，不是已批准的评分函数。体积加权可能忽略细小但视觉显著的部分，`CutCost` 也尚未数学化。

## 先记录的多维证据

| 维度 | 为什么需要 |
|---|---|
| Pattern 拟合误差变化 | 检查是否把单一规律难解释的区域变成更易描述的子区域 |
| 轴可信度与截面规律性变化 | 检查切分是否解除多方向或多峰混合 |
| 凹陷和紧致性变化 | 作为辅助几何解释，不能单独决定 |
| 切割边界与连接代价 | 防止切开后很难在 LEGO 中连接或合并 |
| 目标尺度下的分辨率 | 防止把本来就太小的区域切得更难表达 |

第一阶段保存这些原始维度及人工判断，不急于把它们压成权重和阈值。之后可以比较加权评分、Pareto 排序或数据驱动排序，但选择必须有 benchmark 和 LEGO 求解器结果支持。

## 关键反例

- 小球体：Bulge 拟合简单，但分辨率不足；切成两个半球通常没有净收益。
- 长斜面：Box 填充率低，但 Taper 可能已经充分解释，继续切分只增加成本。
- 两个峰的躯干或尾部：单一 Bulge 拟合不足，峰间切分可能各自产生稳定规律。
- 多分叉区域：父 Shape 的轴可信度低；切后子 Shape 可能各有可靠主轴，但连接边界需另行评估。

## 未解决问题

误差跨尺度如何归一化、子 Shape 如何组合、边界和未来合并成本如何估计，均待实验确定。几何层的停止判断不能替代 Build 阶段的可拼搭性验证。
