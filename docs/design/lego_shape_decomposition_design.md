# 3D Shape → LEGO：自适应几何分块总览

> 状态：算法方案与实验设计阶段，尚未实现或验证。  
> 功能归属：规划中的[模型小工具 / 3D 模型构建 LEGO](./model-tools/model-3d/README.md)。  
> 范围：只讨论 Shape 的 **Split / Build 决策**；局部 LEGO 求解、拼接和 LDraw 生成属于后续阶段。

## 1. 目标与判断框架

输入是连续 3D 模型和目标物理尺寸 `w × d × h (mm)`。整体产品目标是在等比缩放和目标 LEGO 尺度下生成可拼搭、尽量接近原形的模型，并最终导出单个 LDraw 文件。**可拼搭是硬约束，形状相似是优化目标。** 当前方案尚未证明能够达到该整体目标。

对任意 Shape `S`，不先全局体素化，也不预设固定分块深度。先分析其几何规律，再产生并实际评估候选二分：

```text
连续 Shape S + 目标尺寸
  → 目标 LEGO 尺度下的几何分析
  → 尝试用一个主轴与简单规律解释 S
  → 生成候选 S → (S1, S2)，并重新分析子 Shape
  → 切分有显著净收益：Split，递归判断子 Shape
  → 无显著净收益：Build(S)，交给后续 LEGO 求解器
```

这个决策借鉴自适应细分：复杂处进一步分解，简单处保持大块。Box 填充率、凸性、细腰或 Skeleton 分叉都只能提供线索，不能单独作为停止规则。**最终停止理由应是：已经尝试合理候选切分，但没有证据表明切分能使问题更容易。**

## 2. 从停止问题推导出五条脉络

**第一步：为什么不能直接规定何时停止？** 细腰、凸性或 Box 填充率都可能误判。长斜面虽然填不满 Box，却可能只需一种稳定的渐缩规律；接近 Box 的形状也可能有复杂表面。因此“简单”先被定义为**在目标 LEGO 尺度下能否用少量、稳定的几何变化解释**，而不是“像不像 Box”。这提出了一个新问题：怎样观察和比较 Shape 的变化？

### ① 先建立可比较的几何表示

整个 Mesh 难以直接比较变化。先排除缩放后无表达意义的细节，再沿候选方向或路径连续取截面，把三维形态变为截面面积、轮廓、中心和朝向随位置变化的序列。**主轴是组织这些截面的参考路径**：没有路径，就无法判断“沿什么方向保持不变、渐缩或弯曲”。这一步得到多条候选轴及其截面序列；序列本身还不能说明何为“简单”，因此需要下一步。[尺度、主轴与截面专题](./model-tools/model-3d/shape-decomposition/01-scale-axis-sections.md)

### ② 再用几何语言解释变化

尝试用 Constant、Taper、Bend、Bulge 解释截面序列。对每条候选轴分别拟合，选择描述简洁且残差较低的组合。弯曲尾巴需要沿中心路径观察，不能只取 PCA 直线；有些 Shape 则可能没有可靠单轴。这一步得到父 Shape 的规律、拟合残差与轴可信度；若单一规律解释不佳，就要寻找可能使子块各自更简单的切分位置。[几何语言专题](./model-tools/model-3d/shape-decomposition/02-pattern-language.md)

### ③ 从解释失败处提出候选切分

在残差集中处、细腰、凹陷或 Skeleton 分叉等位置提出多个二分候选。这些信号只回答“在哪里试”，不决定必须切。得到若干 `S → (S1, S2)` 后，仍须比较切后是否更好，且不能忽略切割边界的代价。[候选分块专题](./model-tools/model-3d/shape-decomposition/03-split-candidates.md)

### ④ 比较切与不切，决定 Split / Build

为 `S1`、`S2` **各自重新选轴和拟合规律**，比较分前分后的描述难度、目标分辨率与切割/连接代价。有显著净收益才递归 Split，否则 Build。这给出递归停止结构；但几何上更易描述是否真能使 LEGO 更好拼，仍是未经证实的假设。[收益与停止决策专题](./model-tools/model-3d/shape-decomposition/04-split-decision.md)

### ⑤ 用实验检验整条推导链

用人工标注的局部 Shape 先验证四种规律的覆盖率和合理切分的收益，再用真实 LEGO 求解器检查形状误差、零件数、成本与成功率。结果应反过来修正几何语言、轴选择、候选生成或收益定义；不能只靠理论推演固定权重和阈值。[验证专题](./model-tools/model-3d/shape-decomposition/05-validation.md)

这是一条依赖链，而非五种并列算法：**先建立可比较的截面表示，再定义规律与残差；由残差和结构特征提出切分，再用父/子块比较决定是否切；最后用实验检验整条链。** 目标 LEGO 尺度贯穿每一步，不能只在最开始缩放一次就忽略分辨率。PCA、Skeleton、BSP、凸分解与自适应细分提供候选表示或决策思想，并不直接组成可拼搭求解器。

例如弯曲尾巴：PCA 直线可能让截面显得杂乱；沿 Skeleton 路径观察后，截面可能稳定而中心路径平滑转向，于是一个 Bend 就能解释，继续切分未必有益。相反，一个有两个明显鼓起的区域可能无法用单个 Bulge 解释；峰间切分后若两个子块各自近似单峰且边界成本可接受，才有继续 Split 的理由。

## 3. 当前较稳的原则与仍待验证的假设

**当前设计原则：**

- 分块依据连续几何，但必须考虑目标 LEGO 尺度；避免原 Mesh 的微小细节驱动决策。
- 拼接主轴是使截面变化容易解释的路径，不必是最长轴；某些 Shape 可能没有可靠单轴。
- 只有实际尝试切分并比较父/子块，才能判断切分是否值得；切得更小不自动意味着更容易拼。
- 几何拟合难度和 LEGO 离散表达难度必须分开记录。小球即使符合 Bulge，也可能因分辨率不足而难以拼搭。

**尚未验证：**

- Constant、Taper、Bend、Bulge 是否覆盖大多数不值得继续分的局部 Shape。
- 几何拟合残差和切分收益能否预测实际 LEGO 形状误差、零件数、求解成本与成功率。
- 不同尺度的误差如何比较，子块误差、切割边界和未来合并成本如何合成正式 `SplitGain`。

因此当前不固定权重、阈值或“简单 Shape”的最终数学定义，也不把四种 Pattern 当成完备分类。

## 4. 下一步与范围边界

先建立约 20～50 个典型局部 Shape 的实验集合，验证四种 Pattern 的覆盖率；覆盖不足时先修改几何语言。随后评估人工认可的切分是否确实降低描述难度，最后在局部 LEGO 求解器可用后检验几何指标与真实构建结果的关系。具体数据、反例与执行顺序见[验证专题](./model-tools/model-3d/shape-decomposition/05-validation.md)。

当前不深入真实零件召回、Beam Search、块间接口、Merge 重求解、装配路径、结构强度及 LDraw placement。这些是 Build / Merge 阶段的设计和验收问题，不能由 Split 的几何指标替代。
