# ADR：个人组件仓库分组树

## 状态

已采纳，2026-07-25。

## 背景

用户需要独立管理自己上传和订阅的组件，并将同一组件放入多个目录。目录是用户视图，不改变 Component 的所有权、版本、发布状态或存储对象。

## 决策

### 领域边界

- `Component` 继续作为全局逻辑组件，分组不会复制或修改组件。
- `ComponentSubscription` 表示用户对其他用户已启用组件的受管关系。
- `ComponentGroup` 表示单个用户的树节点；所有查询和写入必须带当前 JWT 用户。
- `ComponentGroupMembership` 是自定义分组与组件的多对多直接关系。
- 根节点按用户惰性创建且 ID 稳定；根节点不保存本地化名称，也不保存成员关系。

### 查询语义

- 根节点动态查询“当前用户拥有的全部组件 + 当前仍有效的订阅组件”。
- 自定义节点只查询直接加入该节点的组件，不隐式聚合子树。
- 上传中的 `ComponentImport` 不是 Component，不进入关系表，只在前端根节点视图合并展示。
- 退订在同一事务内删除该用户对组件的所有分组关系。

### 树约束

- 根节点不可重命名、移动或删除。
- 自定义节点最大深度为 8，名称最大 100 字符。
- 同一父节点下名称按去首尾空白并 `casefold` 后唯一。
- 移动前校验用户归属、循环和移动后子树最大深度。
- 删除分组级联删除整个子树及成员关系，但不删除组件。
- 自定义节点通过拖拽调整父节点和兄弟顺序；后端 move API 在单个事务中校验
  循环与深度，并重新编号受影响节点的 `sort_order`。

### 安全与数据库

- API 使用 `require_current_user`，服务层再次按 `owner_id` 隔离。
- 浏览器只携带 Supabase JWT 和 publishable key；不会持有 secret/service-role key。
- 新表启用 PostgreSQL RLS，并撤销 `anon`、`authenticated` 的直接表权限；浏览器只能经业务 API 操作。
- 生产结构只由 Alembic 管理，运行时不创建或补列；本地测试辅助建表函数只服务测试。
- 公共错误只返回稳定 `code + params`。

### 多语言

- 根节点显示名称使用 typed semantic key `componentRepo:groupRootName`。
- 自定义分组名称是用户内容，原文保存并携带 `contentLocale`，不自动翻译。
- ID、类型、排序和关系字段属于机器数据，永不翻译。

## 后续实现原则

1. 新的组件管理视图必须复用“受管组件”查询，不自行拼接所有权和订阅条件。
2. 新的目录能力只能写关系表，不得把目录字段塞进 Component 或版本元数据。
3. 新的订阅入口必须调用同一订阅服务，以保留启用状态检查和退订清理语义。
4. 新的异步任务若操作分组，必须冻结用户 ID 和 locale 上下文，不能读取浏览器后续状态。
5. 新的 UI 文案和 API 错误必须先进入现有 i18n 资源与稳定错误契约。
6. 目录拖拽必须调用原子 move 服务，不得由前端并发交换多个节点的排序值。

## 结果

目录结构与组件生命周期解耦；每个用户拥有独立视图；同一组件可多分组；订阅失效不会留下不可访问的关系记录。
